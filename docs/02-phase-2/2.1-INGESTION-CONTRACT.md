# Phase 2.1 — Ingestion Contract

Status: **IN PROGRESS**

## Objective

Turn arbitrary normalized input into canonical Project Index domain objects while preserving source, evidence, provenance, validation, and atomic persistence semantics.

Phase 2.1 is a capability contract first. Parsers, filesystem discovery, language-specific analyzers, and external connectors are intentionally out of scope.

## Contract

An ingestion operation has five conceptual stages:

```text
input
  ↓
normalize
  ↓
construct canonical domain objects
  ↓
validate + attach evidence/provenance
  ↓
atomic persistence
```

### Input

Input must identify:

- the source/resource being ingested;
- a deterministic payload or normalized representation;
- optional external identity information;
- capture metadata required to explain where the information came from.

The contract must not require a particular parser, transport, filesystem API, or database.

### Canonicalization

Ingestion creates domain values through the existing domain/evidence factories. Callers must not construct structurally compatible objects that bypass normalization or branded IDs.

### Evidence

Every ingested assertion or relationship that represents an observation from an external source must be traceable to evidence. Evidence must retain the source identity and any available locator/excerpt metadata.

### Provenance

Ingestion records the relationship between the created knowledge and its source/evidence. Provenance is explanatory metadata, not a substitute for evidence.

### Validation

Validation runs before persistence. Referential and consistency failures must prevent the affected write from being committed. Validation must not silently turn an unresolved conflict into a fact.

### Persistence

A multi-object ingestion operation is atomic with respect to the supplied `UnitOfWork`:

- all prepared writes commit together;
- any persistence failure rolls the unit of work back;
- validation failure performs no commit;
- the caller receives the structured validation result or original persistence error.

## Determinism

For the same normalized input and equivalent repository state, ingestion must produce equivalent canonical values and equivalent validation outcomes. Runtime timestamps are metadata and must not change semantic identity.

## Acceptance tests

Phase 2.1 is complete only when tests demonstrate:

1. normalized input creates canonical immutable domain values;
2. source/evidence are retained;
3. provenance connects the resulting knowledge to its evidence;
4. invalid references prevent persistence;
5. multiple objects commit atomically;
6. persistence failure rolls back the complete ingestion;
7. repeated ingestion with the same canonical identity follows an explicit duplicate policy rather than silently creating ambiguous facts.

## Explicit non-goals

- filesystem/project discovery;
- language parsing;
- analyzer/plugin execution;
- inference or derivation beyond recording provenance;
- query APIs;
- external connector protocols.

Those capabilities begin in later Phase 2 steps.
